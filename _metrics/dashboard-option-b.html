Key Findings (median values, 4 profiles, 9 tasks)

  • 10 lines beats 1000 lines at 35% less cost. Minimalism’s terse prompt (10 lines) achieves comparable or lower cost to blank on 7 of 9 tasks, while limits-amplified ($0.19 total median) is 35% cheaper than opinionated ($0.29) on matching tasks. Short prompts are not a quality sacrifice.
  • Limits-amplified differentiates on 4 of 9 tasks. Tasks bowling, statistics3, linked-list, and remove-occ show meaningful reductions in cognitive complexity and function length vs. blank. The explicit length and complexity constraints produce measurably better-decomposed code on architecturally flexible tasks.
  • Minimalism is cheapest but fails on complex decomposition. While minimalism wins on cost (lowest total across most tasks), bowling reveals the tradeoff: cognitive complexity 29 and max function length 32 vs. limits-amplified’s 4 and 14. Minimalism’s lack of enforcement allows monolithic solutions to slip through.
  • Judge scores favor limits-amplified on complex tasks (+20 on bowling). LLM judge scores for bowling: limits-amplified 72 vs. minimalism 52 — a 20-point gap on the most architecturally flexible task. For simple tasks (has-close-elements, cmd-hash), scores converge. Judge scores track complexity reduction, not just correctness.
  • A hybrid “compact + constrained” profile is recommended. The data points to a clear optimum: minimalism’s cost efficiency (short prompt, low overhead) combined with limits-amplified’s explicit complexity gates (max function length, cyclomatic thresholds). Neither profile alone dominates; together they would.
  • Opinionated remains the most expensive with diminishing returns. Opinionated costs 35–55% more than blank across all 9 tasks and produces identical output on 5 of 9. Its TDD enforcement and 3-layer hook overhead add cost without proportional quality gains when compared to the lighter-weight limits-amplified constraints.
  • Function count is a useful proxy for decomposition quality. Limits-amplified produces 54 functions on bowling vs. minimalism’s 36 and blank’s -- (monolithic). Higher function counts on complex tasks correlate with lower cognitive complexity — confirming that the constraint “no function longer than N lines” forces real decomposition.

Executive Summary — When Should You Use Each Profile?

The expanded finding: Adding limits-amplified and minimalism reveals a cost-quality frontier that blank and opinionated alone could not show. The frontier is not a line — it’s a two-axis tradeoff between prompt cost (longer prompts cost more) and constraint effectiveness (vague prompts get vague code). Limits-amplified sits at the efficient frontier: specific constraints, low overhead, measurable quality gains on hard tasks.

Use blank when…

Baseline
Reference profile, no prompt overhead

Your tasks are well-constrained: function completions, test-locked implementations, refactoring with existing tests. The code will be identical regardless of profile. Also ideal for high-volume batch jobs where cost dominates and tasks have only one reasonable implementation.

Use opinionated when…

3x
simpler code on bowling — but at 55% cost premium

You need TDD enforcement and are willing to pay for it. The 3-layer hook system and explicit compliance gates produce excellent results on architecturally flexible tasks, but the cost premium over limits-amplified is hard to justify when lighter constraints achieve comparable quality at lower cost.

Use limits-amplified when…

72
judge score on bowling (+20 over minimalism)

You want the best quality-to-cost ratio on architecturally flexible tasks. Explicit complexity limits (max function length, cyclomatic thresholds) produce well-decomposed code at roughly the same cost as blank. This is the recommended default for new feature work and complex algorithm tasks.

Use minimalism when…

Cheapest
lowest total cost on simple tasks

Cost is the primary constraint and tasks are simple or well-constrained. Minimalism’s 10-line prompt achieves blank-equivalent results at equal or lower cost on 7 of 9 tasks. Avoid it for tasks like bowling where architectural choices exist — without explicit limits, Claude defaults to monolithic solutions.

Recommended next step: Build a hybrid “compact + constrained” profile combining minimalism’s brevity with limits-amplified’s explicit complexity gates. Hypothesis: it achieves limits-amplified’s quality at minimalism’s cost. The data predicts a 15–25% cost reduction over limits-amplified with no quality regression on architectural tasks.

Methodology: 4 Claude Code profiles (blank, opinionated, limits-amplified, minimalism) × 9 benchmark tasks × multiple repetitions. All profiles use Claude Sonnet 4.6 with identical task prompts and verification scripts. The only independent variable is the personality configuration. Metrics are median values. Code quality measured via Python static analyzers (cognitive complexity, cyclomatic complexity, function length, function count). LLM judge scores (0–100 scale) available for limits-amplified and minimalism only; judge evaluates readability (JRead) and naming quality (JName) in addition to overall score. Full source: benchmarks/analyzers/.

Limitations: Blank and opinionated lack judge scores (collected in a prior experiment run without the judge pipeline). Function counts for blank and opinionated are not available (“--” in raw data). Judge scores on simple tasks (has-close-elements, cmd-hash, regex-utils) converge across profiles because there is only one reasonable implementation — the judge differentiates primarily on architectural tasks.
