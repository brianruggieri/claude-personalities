Key Findings (n=4 per cell, median values, IQR-confirmed)

  • ex-bowling confirms opinionated produces dramatically simpler code. Cognitive complexity: opinionated 12 [IQR 11–17] vs blank 33 [27.5–38.5] vs main 34 [29.5–38.5]. Max function length: opinionated 19 [17.5–23.5] vs blank 54.5 [45.5–59.5] vs main 62 [55–64]. IQRs do not overlap — this is a consistent, reproducible difference.
  • 4 of 5 tasks produce identical code regardless of profile (he-000, ce-000, rf-001: zero variance across all runs; mbpp-011: overlapping IQRs). Profile differentiation only manifests when the task has high design latitude — multiple valid architectures for the same problem.
  • blank is consistently 35–55% cheaper than opinionated across all tasks and all runs. Cost IQRs do not overlap between blank and opinionated on any task. Main sits between them.
  • The opinionated cost premium only pays off on ex-bowling (+$0.10 over blank) where it produces 3x simpler code. On the other 4 tasks, you pay 35–55% more for byte-identical output.
  • blank and main produce statistically indistinguishable code quality on ex-bowling (IQRs overlap on all metrics). The ~160 lines of personality instructions in main don’t translate into measurable quality improvements — only the enforcement layers in opinionated do.
  • Design latitude is the key predictor of profile impact, not task difficulty. ce-000-regex-utils is “expert” difficulty but test-locked (identical code). ex-bowling is “expert” with multiple valid designs (3x differentiation).
  • Token efficiency varies by profile but not by quality. Opinionated uses more tokens on rf-001 (2103 vs blank’s 1160) yet produces identical code. The extra tokens go to reasoning and compliance checking, not code.
  • Maintainability Index does not differentiate profiles even on ex-bowling (all ~19/100). This composite metric is dominated by line count and Halstead volume, which are similar across profiles. Cognitive complexity and function length are far more sensitive detectors of structural differences.

Executive Summary — When Should You Use Each Profile?

The core finding: Personality profiles don’t affect what code gets written — they affect how it gets structured. When there’s only one reasonable implementation, all profiles converge to it. When there are many valid designs, opinionated consistently chooses the better-decomposed one. The charts above can show you the numbers, but they can’t show you the most important insight: the decision of which profile to use depends entirely on your task mix, not on absolute quality.

Use blank when…

35–55%
cost savings vs opinionated

Your tasks are well-constrained: function completions, test-locked implementations, refactoring with existing tests. The code will be identical regardless of profile, so why pay the prompt tax? Also ideal for high-volume batch jobs where cost dominates.

Use main when…

0%
quality improvement over blank

Surprisingly, main’s ~160 lines of coding preferences (indentation rules, commit style, plugin config) don’t produce measurably different code quality in any task tested. Main’s value is in developer experience (skills, shortcuts, conventions) — not in code output quality. Use it as your daily driver for the DX, not for the code.

Use opinionated when…

3x
simpler code on design-open tasks

You’re building something with real architectural choices: new features, complex algorithms, systems with multiple valid designs. The TDD enforcement and complexity thresholds produce dramatically better-decomposed code. The +$0.10/task premium pays for itself in maintainability.

What the charts can’t show you: The 4 identical-output tasks aren’t failures of the experiment — they’re the most important finding. They prove that personality prompts are not magic. They don’t make Claude “think harder” or “try more.” They constrain the solution space by adding rules (max function length, TDD, complexity gates). When the task already has one obvious solution, the rules have nothing to constrain. This means personality profiles are a precision tool, not a quality dial — deploy them where they matter.
